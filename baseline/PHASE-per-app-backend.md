# PHASE — per-app backend: first-build render + real persistence

_Recorded 2026-07-20. Backend-using apps generated by Buildr101 rendered broken on first load
(a barber site threw "the shop data could not be loaded"; a tracker fell silently to "demo mode").
Root cause was never missing config — it was generated apps touching the owner-scoped backend with
no app-user session on first load, plus public site content having no owner-scoped home. Fixed
caller-side in the builder prompt; no inviolable seam touched. Diagnosis: `DIAGNOSE-per-app-backend.md`._

## What was actually wrong (see DIAGNOSE for the full trace)

Config injection already worked end to end — the barber's `new row violates row-level security
policy for table "entities"` is a **real live-Supabase error**, which only a correctly configured,
connected client produces. `entities` is `owner uuid NOT NULL default auth.uid()` under owner-scoped
RLS. So:
- **Anonymous first-load read** → RLS returns **zero rows** → apps that treated empty as failure threw
  a fatal card.
- **Anonymous write** → `auth.uid()` NULL → **RLS violation**.
- **Public site content** (shop name, services, hours) has no per-user owner, so routing it through
  owner-scoped `db.entity` guaranteed an empty read for signed-out visitors.
- The two failure faces (fatal card vs demo-mode) were purely **non-uniform generated error
  handling** — nothing structural differed.

`proveBackend`/`proveTenancy` always passed because they **sign in first** — the step a first-load
visitor hasn't done.

## The fix (one caller-side lever: the builder prompt)

`src/prompts/builder.mjs` — a shared `BACKEND_MODEL` rules block, applied to the BUILD, both EDIT
(write + apply_patch), and PLAN prompts. It makes every generated app:
1. Render **public site content as in-code constants** (a `SERVICES` array, a `HOURS` object) — never
   fetch site content from `db.entity`.
2. Use `db.entity`/`storage` **only for user-owned records**, gated behind `await auth.currentUser()`.
3. **Never render a fatal card on an empty or failed read** — treat it as a normal empty/seed state.
4. First render must work for a **signed-out visitor with zero rows**, zero iterate turns.

Nothing else changed: the `runTurn` seam, `runtimeEnv` injection, the backend SDK, provisiond,
billing/ledger, and RLS policies are all untouched. Config already arrives (`withRuntimeEnv` →
`.env` → SDK), so no infrastructure was added — backend stays a parameter.

## Proof — `proveBackend` (live, Codex spend)

Sections 1-4 (unchanged): a generated notes app builds, wires auth+db.entity+storage, and
round-trips signUp → signIn → entity.create → list read-back → storage upload → signed-URL
fetch-back against live Supabase.

**New section 5 — FIRST-BUILD RENDER (the regression this phase fixes):** generate a public-content
site ("Ironclad Barbers" booking site) → build with the real backend injected → serve the `dist` →
load it as an **anonymous visitor over the DevTools Protocol with the backend made UNREACHABLE**
(dead proxy + loopback bypass — the true signed-out/failed-read case). Asserts, on the rendered
visible text:
- public shop content is painted ("Ironclad" shown) even with the backend unreachable — proving it
  comes from in-code constants, not a read;
- **no** fatal error card / demo-mode banner;
- the booking UI is present;
- the page rendered real content.

The model's own build summary confirms the intended shape: _"a no-login landing page … visitors can
browse all shop content immediately, while booking is gated behind sign-in … customers can create,
view, and cancel only their own private bookings."_

Render harness note: `--dump-dom`/`--virtual-time-budget` were unusable here (dump races the SPA
mount → empty DOM; vtb hangs on the site's external image loads), so the check drives Edge over CDP —
navigate, let React settle in real time, read `outerHTML` — which is deterministic.

## Isolation & secrets (still hold — unchanged by this phase)

`proveTenancy` green: user B cannot see/read/mutate user A's `entities` rows or storage objects
(owner-scoped RLS, denial = pass). `app_id` namespacing keeps one user's apps apart. No RLS policy
was modified. Secret gate: the anon key is the only credential on the client path; no service-role
material in generated code, the bundle, or the repo (proveBackend/export secret gates green).

## Not done (out of scope / deferred)

- Project-per-app isolation stays the escape hatch, not the default (per DECISION-hosting.md).
- No new "public content" table or public-read RLS path — deliberately avoided (would weaken tenancy);
  public content lives in the app's own code, which is the correct home for site content.
